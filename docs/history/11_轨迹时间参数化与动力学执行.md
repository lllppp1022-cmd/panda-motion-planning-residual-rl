# Phase 2C：轨迹时间参数化与真实动力学执行

本阶段将 Phase 2B 已保存且通过复核的七关节折线路径转换为时间参考，再用原位置伺服执行。它没有重新规划，没有修改控制增益，也没有训练任何神经网络。

## 1. 四组量必须分开

- `q_path`：Phase 2B Shortcut CSV 中的 N×7 路径节点，单位 rad。
- `q_ref、dq_ref、ddq_ref`：对该折线作五次时间缩放得到的参考位置、速度和加速度。
- `ctrl`：原 JointPositionController 在 0.35 rad/s 指令变化限制下，实际写入七个位置执行器的目标角度，单位 rad；不是力矩。
- `q_actual、dq_actual`：MuJoCo 对受重力、阻尼、执行器力限及约束影响的机器人进行 mj_step 后得到的实际状态。

跟踪误差是 `q_actual-q_ref`，不能用 `ctrl-q_ref` 代替。即便参考速度、加速度受限，实际物理状态也不具备相同的硬保证。

## 2. 历史输入冻结与拒绝条件

`src/control/validated_path.py` 读取实际 batch 目录下的成功 JSON、规划结果 CSV、细化复核 CSV 及最终 Shortcut 路径 CSV。必须同时满足 success、final_validation_passed，CSV 与 JSON 路径完全一致、七维有限、首末构型一致。缺失、被拒绝或被修改的记录不能运行。

模型依据来自阶段开始前的 Phase 2B 快照：derived Panda XML、场景 XML、检查器与过滤配置哈希；上游模型及网格继续逐一核对 Phase 1 已保存的 80 个文件哈希。不是在本轮新算哈希后就反称历史模型已匹配。障碍类型、尺寸、静态位置及四元数来自对应试验 JSON，七关节顺序固定为 joint1～joint7。

随后重新建立独立 CollisionChecker，对所有节点及相邻边进行 0.005 rad 复核。`scripts/freeze_phase2c_inputs.py` 保存四场景审计、路径和历史文件哈希、执行配置；不覆盖旧 Phase 2B CSV。原路径文件缺失时不会用重新规划代替。

## 3. 五次时间缩放

对段 i，令 Δq=q[i+1]-q[i]、τ=(t-t_i)/T_i，τ 限定在 [0,1]：

```
s(τ)   = 10τ³ - 15τ⁴ + 6τ⁵
s'(τ)  = 30τ²(1-τ)²
s''(τ) = 60τ(1-τ)(1-2τ)
q_ref  = q[i] + s(τ) Δq
dq_ref = s'(τ) Δq / T_i
ddq_ref= s''(τ) Δq / T_i²
```

s 单调且处于 [0,1]，因此参考构型始终在已经检查的关节直线段上，不使用会产生几何过冲的通用三次样条。每个节点处速度、加速度均为零；代价是每段停稳、路径不具有连续非零速度，jerk 在拼接处不保证连续。

`max|s'|=1.875`，`max|s''|=10/√3≈5.773502692`。代码使用精确系数以免四舍五入造成略微超过阈值：

```
T_i = max(0.10,
          max_j(1.875*abs(Δq_j)/vmax_j),
          max_j(sqrt((10/sqrt(3))*abs(Δq_j)/amax_j)))
```

本轮冻结两档 vmax=0.10、0.15 rad/s，amax=0.30 rad/s²，各场景各速度重复两次。没有为改善成功率事后放松间隙或验收阈值。

## 4. 初始化、控制频率与实际积分

所选四条保存路径起点均不是 home，joint1=-0.65 rad。本轮采用**明确的仿真开始前初始化**：新建独立 live MjData，加载 home keyframe，再在 t=0、physics_steps=0 时一次性写入保存起点、固定夹爪初态和对应障碍姿态，ctrl 设为起点。`initialization.json` 明确记录它不是 home 到起点的物理运动。

初始化之后，`run()` 和原 JointPositionController 均不再写 live qpos/qvel，不执行 reset。控制循环只写 data.ctrl，再调用 mj_step 与用于刷新后积分几何状态的 mj_forward。重新调用初始化会被拒绝。发生意外外部 live 状态修改时拒绝继续正常推进。

物理步长 0.002 s，位置指令及安全监控均为 500 Hz，一步控制对应一次物理积分；没有额外执行环境步。参考采用该物理步结束时刻的 q_ref 作为本步目标，并记录在同一行，控制数据和后积分实际状态有明确时间定义。

开始前保持 1.5 s，至少最后 0.5 s 的最大关节误差≤0.02 rad 且实际最大关节速度≤0.02 rad/s，才开始推进轨迹。启动实际状态与计划起点最大偏差超过 0.02 rad 时直接拒绝，不先瞬移补齐。

到达参考终点后最多等待 2 s，要求最终关节最大误差≤0.02 rad、TCP 误差≤10 mm、实际最大关节速度≤0.02 rad/s，并连续满足至少 0.5 s。成功标准在首次动力学试验前已冻结于 `configs/trajectory_execution.yaml`。

保留原重力、执行器增益/阻尼/力限、耦合夹爪及模型约束。没有额外加入重力补偿，也没有削弱传统控制器，因此可观察到其真实静态误差。参考加速度 0.30 rad/s²不限制初始化保持阶段由重力引起的实际瞬态加速度。

## 5. 每个物理步的实际碰撞监控

每步按实际七关节 q_actual 调用原 Phase 2A state_valid，保留 274 个审计配对、真实硬限位、自碰撞、地面与 5 mm 门槛。该接口固定夹爪；实际动态夹爪会有微小位移，因此还对**相同 274 个配对直接在 live MjData 上查询 mj_geomDistance**，不能只把固定夹爪查询当作所有实际几何的精确结果。

live 数据与查询对象使用相同模型和障碍初态；记录固定夹爪检查与实际 live 间隙、真实夹爪偏差、原生接触、配对是否属于审计集合。最低间隙若达到 distmax 截断范围，仍保留“下界”标记。

任一硬限位、检查异常、禁止接触或间隙≤5 mm+原有数值容差均判失败，记录首个时间、构型和碰撞对象，冻结轨迹时间，转向当前实际关节位置的受限保持。继续积分约 0.5 s 并记录惯性与重力响应；不会假设发出停止命令后机器人瞬间静止。实际跟踪误差超过 0.10 rad、速度超过 1.0 rad/s 或执行预算耗尽也会停止正常推进。

这是仿真中的响应式保护，不是严格连续碰撞检查、刹车距离证明、形式化安全控制器或实机认证。安全监控失败与实际发生接触是不同事件，应分别统计。本轮双障碍场景确实出现“无接触但低于 5 mm”的执行失败，不能抹去。

## 6. 日志、指标和接口

每次执行有独立目录，包含 frozen_run_config.json、initialization.json、tracking.csv、clearance.csv、events.csv、execution_summary.json。失败也归档。

tracking 每个物理步记录仿真时间、轨迹时间、阶段和段号、q_ref/dq_ref/ddq_ref、q_actual/dq_actual、七个实际 ctrl、实际加速度有限差分及 MuJoCo qacc、参考/实际 TCP、距原折线最近距离、间隙与限速计数。规划 q_path 保存在配置及原 CSV，不和参考/执行量混用。

跟踪 RMSE、最大误差与 TCP 跟踪指标统计轨迹推进和最终稳定阶段，失败时仅统计停止前已执行部分。最终到目标误差另外计算；不能把失败途中相对参考的小误差误说成已经到目标。实际速度、加速度峰值统计全段，包括初始化保持与保护保持；报告另列运动阶段峰值。原生接触观察数是逐步累计数量，不是独立碰撞事件数；安全违规步数与首个事件单独记录。

后续可以读取 `QuinticTrajectory.sample(t)` 获得参考与段号，用 `TrajectoryExecutor` 提供的实际 q/qvel、TCP、参考误差、ctrl、间隙及失败状态作为残差控制接口的依据。本轮没有实现残差动作、没有把这些接口接入 PPO/SAC，也没有训练。将来任何残差输出仍需新的动作、安全与执行验收。

## 7. Windows PowerShell 操作

只运行并观看真实动力学：

```powershell
Set-Location D:\mujoco_learning\panda_safe_residual_rl
& D:\miniconda\envs\panda_safe_rl\python.exe scripts/demo_rrt_execution.py --viewer --scene B_sphere --speed 0.10
```

观看并录制 live 动力学 MP4：

```powershell
& D:\miniconda\envs\panda_safe_rl\python.exe scripts/demo_rrt_execution.py --viewer --record --scene B_sphere --speed 0.10
```

窗口明确显示 `DYNAMIC SERVO EXECUTION`、仿真时间、轨迹进度/段号、参考和实际 TCP、实际最近间隙。Esc、Q 或窗口关闭都会停止轨迹推进，继续受限保持并保存日志；不会把用户中止计作成功。不要使用原生 Viewer 的重置、关节滑块或扰动力功能改变试验条件。

不显示窗口的实测入口：

```powershell

```
